# DNS setup

Everything below assumes one mail host, `mail.gsit.nl`, that serves **both**
`gsit.nl` and `stolkies.com`. That is the simplest working setup: one server,
one certificate, one PTR record, any number of mail domains.

Generate a ready-to-paste list at any time with:

```bash
./mailctl dns
```

---

## 0. What you need before touching DNS

| Requirement | Why |
|---|---|
| A server with a **static public IPv4** | mail hosts must not move around |
| **Port 25 outbound open** | most consumer ISPs and some clouds (AWS, Azure, GCP, Hetzner Cloud by default) block it — request an unblock |
| Ability to set **reverse DNS (PTR)** | receivers reject mail from IPs whose PTR doesn't match the HELO name |
| Access to the DNS zones of `gsit.nl` and `stolkies.com` | to publish MX/SPF/DKIM/DMARC |

---

## 1. Host records (zone `gsit.nl`)

```dns
mail.gsit.nl.        3600  IN  A     203.0.113.10      ; your server IPv4
mail.gsit.nl.        3600  IN  AAAA  2001:db8::10      ; only if you really have IPv6 mail working
```

Then set the **PTR** at your VPS/hosting provider (this is *not* in your zone file):

```
203.0.113.10  ->  mail.gsit.nl
```

Check: `dig +short -x 203.0.113.10` must return `mail.gsit.nl.`

> Do **not** publish an AAAA record unless outbound IPv6 mail is fully configured
> with its own PTR — a broken AAAA is a common cause of Gmail rejections.

## 2. Per-domain records

Repeat this block for `gsit.nl` and for `stolkies.com`. Only the zone changes;
both point at the same host.

### 2.1 MX — where inbound mail goes

```dns
gsit.nl.        3600  IN  MX  10  mail.gsit.nl.
stolkies.com.   3600  IN  MX  10  mail.gsit.nl.
```

Nothing else is needed on `stolkies.com` for the host itself — it just borrows
`mail.gsit.nl`. (If you prefer a branded name, add
`mail.stolkies.com. IN CNAME mail.gsit.nl.` and use it as the MX target only if
it resolves to an A record — MX targets may not be CNAMEs per RFC 2181, so
prefer an A record: `mail.stolkies.com. IN A 203.0.113.10`.)

### 2.2 SPF — who may send

```dns
gsit.nl.        3600  IN  TXT  "v=spf1 mx a:mail.gsit.nl -all"
stolkies.com.   3600  IN  TXT  "v=spf1 mx a:mail.gsit.nl -all"
```

* `mx` authorises the hosts in your MX record, `a:mail.gsit.nl` the mail host itself.
* `-all` = hard fail for everything else. Use `~all` (softfail) for the first
  week if other systems (CRM, newsletter tool, website contact form) still send
  as your domain — then add them (`include:...`) and switch back to `-all`.
* **Exactly one** SPF TXT record per domain. Merge, never duplicate.

### 2.3 DKIM — cryptographic signature

Keys are generated by the stack, not by hand:

```bash
./mailctl dkim
```

This writes the keys into `docker-data/dms/config/rspamd/dkim/` and prints the
public records. They look like:

```dns
mail._domainkey.gsit.nl.       3600 IN TXT ( "v=DKIM1; k=rsa; "
  "p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..." )   ; selector "mail"
mail._domainkey.stolkies.com.  3600 IN TXT ( "v=DKIM1; k=rsa; "
  "p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA..." )
```

Notes:
* The selector is `mail` by default; it is part of the record name.
* A 2048-bit key exceeds the 255-char TXT string limit, so it is published as
  multiple quoted strings inside one record. Most DNS panels (Cloudflare,
  TransIP, Hetzner, Route53) accept the whole value pasted as one string and
  split it for you. If yours does not, keep the quoted chunks as shown.
* Verify: `dig +short TXT mail._domainkey.gsit.nl`

### 2.4 DMARC — policy + reporting

Start permissive, then tighten:

```dns
_dmarc.gsit.nl.       3600 IN TXT "v=DMARC1; p=none; rua=mailto:postmaster@gsit.nl; fo=1"
_dmarc.stolkies.com.  3600 IN TXT "v=DMARC1; p=none; rua=mailto:postmaster@stolkies.com; fo=1"
```

Roll-out schedule:

| Week | Policy |
|---|---|
| 1–2 | `p=none` — collect reports, fix any source that fails SPF/DKIM |
| 3–4 | `p=quarantine; pct=25` then `pct=100` |
| 5+  | `p=reject` |

### 2.5 Client autodiscovery (optional, but saves support calls)

```dns
autodiscover.gsit.nl.        3600 IN CNAME mail.gsit.nl.
autoconfig.gsit.nl.          3600 IN CNAME mail.gsit.nl.
_imaps._tcp.gsit.nl.         3600 IN SRV   0 1 993 mail.gsit.nl.
_submission._tcp.gsit.nl.    3600 IN SRV   0 1 587 mail.gsit.nl.
; same four for stolkies.com
```

### 2.6 MTA-STS / TLS-RPT (optional hardening, add once mail flows)

```dns
_mta-sts.gsit.nl.   3600 IN TXT "v=STSv1; id=20260101000000"
_smtp._tls.gsit.nl. 3600 IN TXT "v=TLSRPTv1; rua=mailto:postmaster@gsit.nl"
```

Requires an HTTPS endpoint at `https://mta-sts.gsit.nl/.well-known/mta-sts.txt`.
Skip until the basics are green.

## 3. Complete example zone snippets

**gsit.nl**

```dns
mail.gsit.nl.             IN A     203.0.113.10
gsit.nl.                  IN MX    10 mail.gsit.nl.
gsit.nl.                  IN TXT   "v=spf1 mx a:mail.gsit.nl -all"
mail._domainkey.gsit.nl.  IN TXT   "v=DKIM1; k=rsa; p=<from ./mailctl dkim>"
_dmarc.gsit.nl.           IN TXT   "v=DMARC1; p=none; rua=mailto:postmaster@gsit.nl; fo=1"
autodiscover.gsit.nl.     IN CNAME mail.gsit.nl.
autoconfig.gsit.nl.       IN CNAME mail.gsit.nl.
```

**stolkies.com**

```dns
stolkies.com.                  IN MX    10 mail.gsit.nl.
stolkies.com.                  IN TXT   "v=spf1 mx a:mail.gsit.nl -all"
mail._domainkey.stolkies.com.  IN TXT   "v=DKIM1; k=rsa; p=<from ./mailctl dkim>"
_dmarc.stolkies.com.           IN TXT   "v=DMARC1; p=none; rua=mailto:postmaster@stolkies.com; fo=1"
autodiscover.stolkies.com.     IN CNAME mail.gsit.nl.
autoconfig.stolkies.com.       IN CNAME mail.gsit.nl.
```

## 4. TLS certificates (Let's Encrypt)

Self-signed certificates are generated by `./setup.sh` so the stack works
immediately. For production, get a real certificate for `mail.gsit.nl` **after**
its A record resolves:

```bash
docker run --rm -it \
  -v "$PWD/certs:/etc/letsencrypt" \
  -p 80:80 \
  certbot/certbot certonly --standalone -d mail.gsit.nl \
  --agree-tos -m postmaster@gsit.nl --no-eff-email
```

Then in `mailserver.env`:

```env
SSL_TYPE=letsencrypt
```

and `docker compose restart mailserver`. Renew with the same command (or a cron
job) plus a restart; `./certs` is already mounted read-only into the container.

One certificate for `mail.gsit.nl` is enough for both domains — clients connect
to that hostname regardless of their email domain.

## 5. Verification checklist

```bash
dig +short MX gsit.nl                       # -> mail.gsit.nl.
dig +short MX stolkies.com                  # -> mail.gsit.nl.
dig +short TXT gsit.nl                      # -> v=spf1 ...
dig +short TXT mail._domainkey.gsit.nl      # -> v=DKIM1 ...
dig +short TXT _dmarc.gsit.nl               # -> v=DMARC1 ...
dig +short -x 203.0.113.10                  # -> mail.gsit.nl.
openssl s_client -connect mail.gsit.nl:993 -brief   # certificate check
```

End-to-end:

1. Send a mail from a mailbox on the server to **https://www.mail-tester.com** —
   aim for 10/10.
2. Or mail `check-auth@verifier.port25.com` and read the reply: SPF, DKIM and
   DMARC must all say **pass**.
3. Send a mail *to* `postmaster@stolkies.com` from Gmail and confirm it lands in
   the webmail inbox.

Common failures:

| Symptom | Cause |
|---|---|
| Mail to Gmail bounces `550 5.7.1` | missing/incorrect PTR, or no SPF/DKIM |
| Inbound mail never arrives | MX missing, port 25 blocked inbound, firewall |
| DKIM `permerror` / `none` | record published under the wrong selector name |
| SPF `permerror` | two SPF TXT records on the same domain |
| Clients warn about the certificate | still on self-signed, see section 4 |
